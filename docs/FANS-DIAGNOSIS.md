# 1.3.19-im.3 粉丝加载排查版

内部版本号 63，基于 im.2。用户真机反馈：关注列表正常，粉丝入口已能打开，但加载时显示泛化的“奇怪的错误”。该截图没有提供具体异常，尚不能确认用户账号下的根因。

## 本次修正

- 粉丝请求改为参考实现使用的 HTTPS tiebac.baidu.com 地址，不更改其他客户端接口的地址。
- 共用 Flow 请求适配器不再对失败响应直接强制解包 response.body；非成功 HTTP 响应保留状态码，空响应报明确错误。
- 粉丝页增加具体错误说明（异常类型、应用内位置及经过凭据脱敏的说明），避免通用错误页隐藏原因；不显示响应正文。
- 首次加载尚未成功时，粉丝标题不再显示默认的 0。刷新失败时保留之前成功加载的数量。
- 单条 null/无效账号记录不再令整个粉丝页失败；如果本页没有任何有效账号，则明确报错，不把它当作没有粉丝。

## 已做验证及边界

无登录凭据的真实请求对照：HTTP c.tieba.baidu.com、HTTPS c.tieba.baidu.com、HTTPS tiebac.baidu.com 均返回 HTTP 200、error_code=0 和合法的 user_list/page 结构。无登录态下返回的数量不能当作用户实际粉丝数量。

新增测试通过真实 OfficialTiebaApi Retrofit 服务声明、Flow 适配器、空响应转换器和 Gson 响应转换器验证 URL、pn/uid 请求字段、嵌套分页及数字字符串解析；HTTP 403 保留状态码；HTTP 200 空正文得到明确错误。网络在测试中被本地响应替代，没有提供登录凭据。

现有通用 JSON 客户端还包含 kotlinx 序列化回退层、账号公共参数、签名、登录检查和网络检查。本地测试没有使用这些依赖 Android/登录环境的完整组件，因此不能等同于真机账号测试。

没有在手机上复现或使用用户账号请求粉丝列表。此版本主要用于修正确定存在的错误处理缺陷、兼容无效账号记录并取得下一步所需的具体错误，不能宣称该账号的粉丝加载已修好。如仍失败，应提供新错误页截图；不需要提供登录凭据。

保留 im.2 的回帖数字跳转、粉丝入口、18 修订 2 的主页和刷新修复，以及 im.1 的私信握手修复。
