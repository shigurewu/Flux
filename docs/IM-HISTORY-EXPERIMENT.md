# 1.3.19-im.5：历史私信读取尝试

内部版本号 65，基于 im.4。保留私信表情、折叠消息、粉丝解析等已有修改。

## 使用

进入具体聊天，点击顶部“同步历史消息（尝试）”。每次请求一页；返回还有历史时，可点击“继续同步更早消息”。页面显示新增记录数、暂不支持的非文本消息数，或实际失败原因。请求未结束时禁止重复点击。

这是尝试版，尚未用已登录账号验证该接口是否仍能返回私信。无需向开发者提供密码或登录凭据；读取请求仅使用应用内当前账号的登录态，发送至 HTTPS 贴吧域名。不自动跟随重定向，不记录请求内容或消息正文。

## 依据与已验证的范围

公开项目 [ccloli/Tieba-Chat 的历史实现](https://github.com/ccloli/Tieba-Chat/blob/8efb4cd31f6217e53d479a362d68804e5b0ddc6f/tb_chat.user.js) 调用 `/c/s/historymsg`，参数包含 `com_id`、`msg_id`、`user_id`；使用最早消息 ID 继续向前分页，返回 `message` 和 `has_more`。本版依据该调用约定实现，客户端版本参数沿用样例的 4.2.7，并沿用项目现有表单签名方法。

2026-11-13 对 tieba.baidu.com 和 c.tieba.baidu.com 的该路径进行了不带登录凭据的 POST 探测（版本参数 6.0.0）：均返回 HTTP 200、JSON error_code=1、“用户未登录”。这只证明路径当前有响应，不证明接口登录后仍可读到历史，也不证明历史保留范围。

本地官方贴吧 22.13.1.1 APK 中存在 `protobuf.QueryHistoryMsg` 模型，但未找到私信页面使用它的证据；其字段含 forumId，不能凭名称认定为当前私信云历史接口。找到的 LoadPersonalHistoryMessage 调用链最终读取本地 DAO；APK 另有通用 IM SDK 的网络历史方法，但没有证明它与目前 Flux 使用的私信协议兼容。本版未猜测其命令号或使用未知 gettype 值。

## 数据处理

- 所有记录按当前账号、对端隔离；切换聊天或账号会取消相关读取，入库前后再次检查归属。
- 旧接口消息编号保留在负数命名空间，groupId=-1，避免冒充实时 WebSocket 编号。读取历史不修改实时游标、发送编号、会话预览和未读总数，也不会发送已读回执。
- 相同历史 ID 重复读取由 Room 唯一索引去重。如果实时消息的编号、发送者、时间和内容均与历史记录一致，列表只显示实时记录；不同 ID 的相同文字仍保留。
- 从用户主页进入一个尚无本地会话的聊天时，成功导入文本会建立本地会话入口；已有会话的预览和未读状态保持原样。
- 历史消息与本地记录按时间显示。不会因为补入旧记录而自动跳到底部。退出后已导入记录保留；分页位置不持久化，重新进入时从旧接口首页读取，已有记录会去重。
- 只导入文本及文本里的内置表情标记。图片、语音等暂不支持，会计数提示。
- 响应结构不匹配、登录拒绝、游标不向前或空页仍声称有下一页均报告失败，不当成“没有历史”。响应体上限 2 MiB，每次只读取一页。
- “服务端本次未提供更多历史”只描述此次接口结果，不代表官方客户端所有记录已同步。

## 验证

新增回归测试覆盖收发方向、精确 Long ID、历史与实时 ID 隔离、登录错误、畸形响应、重复/倒退分页、非文本跳过、重复页稳定编号、跨协议严格去重及明确结束标记。

未进行手机运行、真实登录接口响应、完整历史恢复验证。若返回登录失败或格式不匹配，需要以手机上实际错误继续定位，不能据此宣称账号没有历史记录。
