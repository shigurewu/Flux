# 1.3.19-im.2：我的页面入口修复

内部版本号 62，基于 1.3.19-im.1。此前“我的”页的粉丝、回帖数字没有绑定点击事件，并非点击后接口请求失败。

## 本次行为

- 点击“我的”页粉丝数字：进入粉丝列表。
- 点击个人主页粉丝数字：进入该用户的粉丝列表。
- 点击“我的”页回帖数字：打开自己的个人主页并直接选择“回复”标签；手机布局和宽屏布局均传递初始标签。
- 粉丝列表沿用现有用户列表的头像、昵称和主页跳转，支持刷新、分页和错误重试。
- 粉丝与关注使用不同请求和状态键。粉丝页面不沿用关注页面的“已关注/取消关注”按钮，避免把粉丝关系误当作本人关注关系。

## 接口与错误处理

新增 /c/u/fans/page 请求，传递 uid、pn 和客户端版本。粉丝响应使用 user_list 和嵌套 page（current_page、total_count、has_more），不按关注接口的 follow_list 结构解析。

错误响应、缺失分页/列表、无效用户 ID 不显示为“没有粉丝”，而交给现有错误页面显示并重试。数字字符串和嵌套分页有独立解析测试。

参考：[aiotieba 粉丝请求](https://github.com/lumina37/aiotieba/blob/5baf2ab5539606c0b346cba7105145fe7330129b/src/aiotieba/api/get_fans/_api.py)、[响应结构](https://github.com/lumina37/aiotieba/blob/5baf2ab5539606c0b346cba7105145fe7330129b/src/aiotieba/api/get_fans/_classdef.py)。本次没有使用登录凭据请求粉丝列表。

## 验证范围

编译会检查生成的页面路由与调用参数；单元测试覆盖粉丝响应解析、正常空列表、服务端失败与不完整数据。没有在手机上实际点按，也没有验证当前登录账号的粉丝接口返回。

本版保留 im.1 的私信握手修复和入口，实际账号鉴权、收发仍需设备验证；18 修订 2 的主页可见范围与动态刷新修改继续保留。
